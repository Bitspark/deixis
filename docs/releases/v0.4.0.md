# deixis v0.4.0

This release **changes no bytes**. The node model and the `deixis-codec-v2` **candidate**
contract are those of [v0.3.0](v0.3.0.md), and every flat artifact and every `dxl2`
address this release produces is the one v0.3.0 produces. What is new:

- the contract now states what a lazy **navigation** judges;
- the corpus can observe navigation;
- the corpus is measured by mutation and by differential fuzzing;
- deixis joins the **substrate catalog**.

## Status: still a candidate, not frozen

Nothing about the freeze has changed since v0.3.0. The freeze manifest is not signed, so
bytes and addresses are **not stable identities**: a change to the contract before the
freeze changes them. No implementation here is the clean-room implementation
[design/0007](../design/0007-clean-room-commission.md) calls for, and no core claims frozen
conformance (CODEC.md §16).

## What changed in the contract

[CODEC.md](../CODEC.md) §14 now pins **what a navigation judges**
(deixis-internal#38). A navigation is resolve-root once,
then resolve-child for each key of a path. §14 required both constructors of every
`linked-resolver` already; the pins say what a navigation owes the chunks it passes
through:

1. **Every fetched chunk's whole framing, before the chunk is used.** Its size at fetch,
   then the hash it was reached by, then its complete §6 framing, every entry included.
2. **The slot codec only at the chunk it answers with.** Capability, then payload, of
   that chunk alone. A payload the navigation passes through is never decoded.
3. **Faults are met in fetch order.** Along a path the order is forced, not chosen.

All four cores already behaved this way. The pins change no byte and no address. No
committed vector changed either: since v0.3.0 the corpus has only grown.

## Validation

The live counts are in [EVIDENCE.md](../EVIDENCE.md), bound to the harness output.

- **Conformance against an independent corpus.** At the release commit each of Rust, Go,
  TypeScript and Python passes all **3214** harness checks: 2846 for the codec (2833 requests and 13 envelope requests) and 368 for the node model.
  v0.3.0 had 2735. The corpus gained:
  - key-order cases on both sides of 0x80 (deixis-internal#37);
  - navigate cases for §14's two constructors and the new pins
    (deixis-internal#39,
    deixis-internal#47), served by a new `codec.navigate`
    operation in all four CLIs (deixis-internal#44) and
    sent on every run since deixis-internal#45;
  - second cases wherever a mutation was killed by two checks or fewer
    (deixis-internal#48).

  All were authored from the contract text by the vectors lane. **115 cases** (deixis-internal#16)
  predate any implementation, and deixis-internal#39's navigate cases predate any core serving the
  operation. The rest were written while implementations existed, and no expected value
  was taken from an implementation's output.
- **Conformance-suite mutation.** `tools/conformance/mutants.mjs`
  (deixis-internal#36) plants design/0006's named defect
  classes in each core, at every site that core's source shows, and asks whether the
  corpus notices. Its first run found eight corpus gaps, and later ones found a
  requirement no request could reach; the corpus now covers both. **Reading at
  `555cc3b`:** 65 plants, **62 killed, 0 survived**, and no kill rests on fewer than 3
  checks. 3 plants sit outside every §2.1 profile (Python's one-chunk builder, covered by
  unit tests), and Go's host-string class is an equivalent mutant there. This is a reading
  at one commit: the runner is not in CI.
- **Cross-language agreement, not conformance.** `interop.mjs --fuzz`
  (deixis-internal#35) mutates canonical octets and checks
  that every core gives each mutant the same answer (law 3), and that each core reads any
  split of it as it reads the whole buffer (§14). CI runs it on fixed seeds. A 40-seed
  sweep of 80,000 mutants found no disagreement.
- **Proofs.** [CODEC-proofs.md](../CODEC-proofs.md) is unchanged.

## The substrate catalog

deixis joins the substrate catalog as **two components**
(deixis-internal#51):

- `deixis`: the core, with `deixis-core` (Rust), `@bitspark/deixis-core` (TypeScript) and
  the Go module `github.com/bitspark/deixis`;
- `deixis-pos`: the positional profile, with `deixis-pos` and `@bitspark/deixis-pos`, in
  the same Go module.

This is membership, not graduation: deixis stays a draft (ADR 0014 §6). v0.4.0 is the
first release that emits publisher manifests, for atlas to assemble into the catalog.

## Distribution

The repository-wide source tag is `v0.4.0`. The coordinated Rust and TypeScript package
versions are `0.4.0`. The release publishes `@bitspark/deixis-core` and
`@bitspark/deixis-pos` to GitHub Packages. Go and Rust consume the source tag. Python
remains source-only, and the TypeScript set package remains private.

## What remains before the freeze

Unchanged since v0.3.0, and beyond this repository's reach alone:

1. **A clean-room implementation** from the specification with the vectors withheld
   ([design/0007](../design/0007-clean-room-commission.md)). The commission has not been
   sent.
2. **A consumer's end-to-end rehearsal** with the exact candidate bytes, then a soak.
3. **A signed, independently mirrored freeze manifest.** The fuzz and mutation reports
   above are inputs to it ([issue #1](https://github.com/Bitspark/deixis/issues/1)).

# deixis v0.6.0

The first public release. deixis was developed in a private repository through v0.5.0;
this repository starts from a fresh history, and v0.6.0 is its first tag. The model, the
API and the candidate codec are those of v0.5.0. What changes is where deixis lives, how
it is licensed, and where its packages are published.

## No byte or address changed

`deixis-codec-v2` is unchanged since v0.3.0: no encoding, no address and no corpus case
differs. Its consumer byte-profile name therefore stays
`deixis-codec-v2/identity-bytes@v0.4.0`. [CODEC.md](../CODEC.md) §16, which gained its
rule for these names after v0.5.0, says a release that changes no byte and no address
keeps every name, and a consumer that recorded one MUST NOT change it on adopting such a
release. The codec is still a candidate and is not frozen;
[issue #1](https://github.com/Bitspark/deixis/issues/1) tracks what the freeze needs.

## License

Apache License 2.0, replacing `MIT OR Apache-2.0`. Versions published before v0.6.0 keep
the license they were published under.

## Where to get it

| Language | v0.5.0 and earlier (private) | v0.6.0 |
| --- | --- | --- |
| Go | `github.com/bitspark/deixis`, from the private repository | the same module path, from this repository and the public module proxy |
| TypeScript | `@bitspark/deixis-core`, `@bitspark/deixis-pos` on GitHub Packages | the same names on npmjs, with provenance |
| Rust | `deixis-core`, `deixis-pos` as git dependencies on a tag | `bitspark-deixis-core`, `bitspark-deixis-pos` on crates.io |
| Python | source of a tag | unchanged: source of a tag |

**Rust:** the bare name `deixis` is taken on crates.io, so the published crates take the
vendor prefix that mirrors the npm scope. The library names are pinned, so code is
unchanged: `use deixis_core::...` still resolves. Only the dependency line changes:

```toml
[dependencies]
bitspark-deixis-core = "0.6.0"
```

**Go:** the module path is unchanged, but the tags v0.1.0 to v0.5.0 do not exist in this
repository. They were never in the public module proxy either, so a consumer pinned to
one of them must move to v0.6.0; nothing older resolves from here.

**TypeScript:** if an `.npmrc` maps the `@bitspark` scope to GitHub Packages, v0.6.0
resolves from npmjs only once that mapping is removed or overridden for these packages.

The set profile (`set/`) stays source-only in both registries, as it was.

## The corpus is public

The conformance corpus in [vectors/](../../vectors/) is public with the rest of the
repository. The clean-room commission that the codec's freeze requires still withholds
it, per implementer rather than by access control: [design record 0007](../design/0007-clean-room-commission.md)
and [vectors/README.md](../../vectors/README.md) say how, and what that is weaker than.

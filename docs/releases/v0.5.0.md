# deixis v0.5.0

This release exposes the shared structural binding for `DataTree` and
`WireTree`, under [ADR 0012](../design/0012-data-wire-tree-symmetry.md).
The primitives are addressless `Data.read()` and `Wire.send(message)`;
both tree types instantiate `DeixisNode<T>` with the same complete structure.
deixis continues to treat `T` as opaque and implements neither operation.

## Breaking TypeScript change

`node.own` becomes `node.own()`. A callable payload changes from
`node.own(arg)` to `node.own()(arg)`. The core, codec, set profile, and
conformance adapters use the method form.

The core exports `DeixisNode<T>`, `Key`, `Path`, and `Parts<T>`.
`Node<T>` implements the interface directly, including `children()` for the
complete child map. `entries()` remains available. `Node.compose` remains
the native constructor and `decompose` returns its complete parts. The exported
`compose` reconstructs interface parts, including independently implemented
children, without requiring the native `Node` class.

Go adds the same recursive `DeixisNode[T]` projection and `AsTree` adapter
for native `Node[T]` values. `ComposeTree` reconstructs parts at the shared
interface boundary. Rust and Python retain their native bindings to the same
structural model. [API.md](../API.md) lists the exact signatures.

## Capability trees and snapshots

`DataTree` contains Data readers. Materializing it reads those payloads into
a `Node[Bytes]` snapshot, preserving its exact-byte-keyed structure. The
snapshot can be encoded by the existing identity-bytes codec. Neither
reader capabilities nor Wire capabilities are serialized by that codec.

The node laws and all candidate codec bytes, profiles, slot-codec identifiers,
and address domains are unchanged. `deixis-codec-v2` remains **candidate,
not frozen**. The existing `deixis-codec-v2/identity-bytes@v0.4.0` consumer
profile does not become a new byte profile because this API version changed.
Previous release tags remain immutable.

## Distribution and validation

The repository-wide source tag is `v0.5.0`. Rust and TypeScript package
versions are coordinated at `0.5.0`. The established release workflow
publishes the private `@bitspark/deixis-core` and `@bitspark/deixis-pos`
packages to GitHub Packages. Go and Rust consume the source tag; Python
remains source-only, and the TypeScript set package remains unpublished.
Public bitwire and bitstore libraries do not acquire this private dependency.

Validation includes the TypeScript core, positional and set suites; Go native
and projection tests; the unchanged shared conformance corpus; and the
existing codec/specification checks. New binding tests exercise binary keys,
the two primitive operations, and missing versus refusing children. CI also
runs all four cores and the cross-language codec agreement checks. A sibling
consumer's implementation status is established by that consumer's tests
and release, not by this release's naming decision.

# deixis v0.3.0

This release adds the canonical bytes of the current node model. Rust, Go, TypeScript
and Python each implement the `deixis-codec-v2` **candidate** contract
([CODEC.md](../CODEC.md), chosen in
[ADR 0011](../design/0011-codec-for-mandatory-nodes.md)). The node model and the
node APIs are unchanged from [v0.2.0](v0.2.0.md):

```text
Node[T] = T × FinMap[Bytes, Node[T]]
```

## Status: a candidate, not frozen

The contract's freeze manifest is not signed. These are candidate implementations of a
candidate contract (CODEC.md §16):

- **Bytes and addresses are not stable identities.** A change to the contract before
  the freeze changes the octets and the `dxl2` addresses this release produces. Do
  not persist them as durable names, and do not sign them expecting them to survive.
- **No implementation here is the clean-room implementation** that
  [design/0007](../design/0007-clean-room-commission.md) calls for. All four were
  written in-house, by implementers who had read the independent corpus.
- **Conformance claims are scoped** by the profiles each core implements (§16), listed
  below. None of them claims frozen conformance.

## What the codec encodes

Every node's own payload and its complete child map, in one production:

```text
flat   := "dxf2" ‖ cuvarint(len(id)) ‖ id ‖ node
node   := cuvarint(len(payload)) ‖ payload ‖ cuvarint(count) ‖ entry*
entry  := cuvarint(len(key)) ‖ key ‖ node
```

Keys are unique and strictly ascending in unsigned-lexicographic order, with a shorter
prefix first. Every integer is a shortest-form `cuvarint` in `0 … 2^64 − 1`. A childless
node is its framed payload followed by `00`. The earlier `Leaf | Struct` candidate
(`deixis-codec-v1`) was withdrawn before any freeze or implementation, and no v1 bytes
or addresses exist to convert.

The payload is written by a **slot codec** that the header names by its id:

| Slot codec | Id | Payload |
| --- | --- | --- |
| identity-bytes | `00 01` | the octets themselves |
| option-of(c) | `02 ‖ id(c)` | `00` for none, `01 ‖ e_c(x)` for `Some(x)` |

A decoder is given the slot codecs it **holds**. Option-of over a held codec is held,
to any depth that fits the 32-octet id. A header naming any other codec is refused as
`unsupported_slot_codec`, never guessed at. Payloads are values, not behaviour: a codec
for handler names serializes the names, and binding a name to behaviour stays the
consumer's act.

The **linked form** stores one chunk per node, `"dxl2" ‖ id ‖ links ‖ body`, with
children referenced through a header of SHA-256 chunk hashes in first-use order.
Shared subtrees are therefore stored once. An address is always the pair
(`dxl2`, digest), never a bare digest, and the flat form's digest is never an address.

## Verdicts, limits and streaming

A decoder judges framing first, then whether it holds the slot codec, then every
payload. So a malformed artifact (one flat artifact, or one chunk) gets exactly one
verdict. Within §12's floors it is the same in every conforming implementation (§8, §10,
§11). Verdicts fall into four classes that are never collapsed:

- `invalid`: the octets are not canonical `deixis-codec-v2`;
- `unsupported`: framing is well formed, and this reader does not hold the codec;
- `incomplete`: streaming only, `need_more_input`;
- `resource-refused`: `limit_exceeded`, naming one of §12's dimensions.

Store faults (`missing_chunk`, `hash_mismatch`) are reported separately and are never
verdicts. Every limit defaults to §12's floor, and every limit is met in parse order.
A streaming decoder reaches the whole-buffer verdict for every split of the input.
Resolving a linked value verifies the root against the requested address and each
child against its parent's link. Materializing or flattening takes an explicit budget,
checked with saturating arithmetic before anything is built. That is how a sharing bomb
is refused without being unfolded.

## Laws

For every lawful slot codec:

- `decode(encode(n)) ≡ n`
- `encode(n) = encode(m)` if and only if `n ≡ m`
- `encode(decode(b)) = b` for every accepted `b`

`≡` is node equivalence under the slot codec's own equivalence. Option-of is lawful
whenever its inner codec is. [CODEC-proofs.md](../CODEC-proofs.md) proves these
concretely for this byte format. The proofs are mathematical, not proof-assistant
verification; the paper's abstract encoder is not evidence for a byte format.

## API

The node APIs are unchanged from v0.2.0. The codec is added alongside them:

| Language | Codec entry point |
| --- | --- |
| Rust | `deixis_core::codec` (the crate stays dependency-free; SHA-256 is its own module) |
| Go | package `deixis` in `core/go` (`EncodeFlat`, `DecodeFlat`, `EncodeLinked`, `ResolveRoot`, …) |
| TypeScript | `@bitspark/deixis-core/codec`, a subpath export; the package's main entry is unchanged, and the library stays free of `node:` imports |
| Python | `deixis_codec` in `core/py`, source-only |

[API.md](../API.md) lists each operation in each language. Every decoder returns an
accepted value together with the slot codec it was decoded under (CODEC.md §4). Every
decoder exposes the four verdict classes distinctly, and reports store faults
separately. Each core resolves a linked value through separate resolve-root and
resolve-child constructors (§14).

## Validation

Each claim below is labelled by what kind of evidence it is. The live counts are in
[EVIDENCE.md](../EVIDENCE.md), bound to the harness output.

- **Conformance against an independent corpus.** The vectors lane authored the codec
  corpus from CODEC.md. Its first 115 cases
  (deixis-internal#16) were written before any
  implementation existed. The cases added later
  (deixis-internal#20,
  deixis-internal#24,
  deixis-internal#29) were also derived from the
  contract text. Some were prompted by implementation reports and by reading the CLIs,
  but no expected value was taken from an implementation's output. Neither the spec
  author nor any implementer wrote an expected encoding of a node or a chunk.
  `node tools/conformance/harness.mjs` replays the corpus through each core's
  black-box CLI.
  - At the release commit, each of Rust, Go, TypeScript and Python passes all 2735
    harness checks: 2367 for the codec (2356 requests and 11 envelope requests) and
    368 for the node model. CI runs them on every change.
  - Pair cases witness the identity law's pair-shaped obligations.
  - Split cases witness streaming.
  - Budget cases witness the resource envelope, including a sharing bomb refused
    within a wall-clock bound.
- **Cross-language agreement, not conformance.** `tools/conformance/interop.mjs`
  generates seeded values under identity-bytes, option-of and a test setoid. It then
  checks four things across the four cores:
  - they produce identical flat octets and identical linked chunk sets;
  - each decodes every other's octets back to the original under ≈;
  - law 1 holds in both directions.

  CI runs it on fixed seeds, so the gate is deterministic; run without `--seed` it
  draws and prints a fresh one. Its first run found a real defect the corpus could not
  reach: the Python CLI read stdin in the locale's encoding. A corpus case now pins
  that as well.
- **Property tests in each core** state no encoded octets: round trip, canonical
  re-encoding, identity iff ≈, exactness under single-octet mutation, split
  invariance, sharing, store faults, and every §12 dimension at and over its limit.
- **Proofs.** [CODEC-proofs.md](../CODEC-proofs.md) proves the laws for this byte
  format.

Two rounds of implementation reports found gaps in the contract that the corpus
could not reach: where a budget is checked, what a limit is met on, and how an id
ends. They were settled in the contract itself before any core shipped, in
deixis-internal#21 and
deixis-internal#27. No committed vector changed its
verdict.

## Distribution

The repository-wide source tag is `v0.3.0`. The coordinated Rust and TypeScript package
versions are `0.3.0`, including the unchanged positional and set implementations. The
tag workflow publishes `@bitspark/deixis-core` and `@bitspark/deixis-pos` to GitHub
Packages. Go and Rust consume the source tag. Python remains source-only, and the
TypeScript set package remains private because it imports the sibling core build.

## What remains before the freeze

The freeze process of [design/0006](../design/0006-canonical-codec.md) still requires,
beyond this repository's reach alone:

1. **A clean-room implementation** from the specification with the vectors withheld,
   with its independence lineage recorded
   ([design/0007](../design/0007-clean-room-commission.md)). The commission has not
   been sent.
2. **An end-to-end rehearsal** with the exact candidate bytes by a consumer (signatures,
   bridging, packing, retrieval, corruption, closure validation, garbage-collection
   races, crash and power loss), then a soak with the contract unchanged.
3. **A signed, independently mirrored freeze manifest.** It lists the specification,
   the proofs, the registry snapshot, the corpus and a clause-to-vector traceability
   matrix, the implementation commits and build instructions, fuzz and mutation
   reports, known assumptions, the external address syntax, and the errata and
   collision-response policies.

[Issue #1](https://github.com/Bitspark/deixis/issues/1) records the delivery and these
obligations. Wire, nightseam, bittree, ontos and Topos adoption stays with the owning
repositories; this release does not certify or change those consumers.

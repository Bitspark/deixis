# deixis v0.2.0

This breaking release implements [ADR 0010](../design/0010-mandatory-node-values.md)
in Rust, Go, TypeScript and Python. Every existing node has a caller-supplied value,
independently of its children:

```text
Node[T] = T × FinMap[Bytes, Node[T]]

decompose : Node[T] → T × FinMap[Bytes, Node[T]]
compose   : (T × FinMap[Bytes, Node[T]]) → Node[T]

compose(decompose(n)) ≡ n
decompose(compose((t, children))) ≡ (t, children)
```

The own value is opaque to deixis. A node can have both a value and children, and
adding a fresh child preserves every existing value and path. Reconstruction takes
the parent value and the complete map of whole child subtrees; children alone do
not determine a parent. Equality delegates the whole value to the caller's
relation at each corresponding node.

## Migrating from v0.1.0

The published v0.1.0 API used `Leaf(T) | Struct(children)`. Replace those alternatives
with one constructor taking an own value and children. Supply a parent value when
building a group. A childless node still has a value; there is no generic empty
node for arbitrary `T`.

| Language | Construction | Complete parts | Own value | Path lookup |
| --- | --- | --- | --- | --- |
| Rust | `Node::compose(value, children)` | `node.decompose()` (consumes the node) | `node.own()` → `&T` | `node.at(path)` → `Option<&Node<T>>` |
| Go | `deixis.Compose(value, children)` | `node.Decompose()` | `node.Own()` → `T` | `node.At(path)` → `(Node[T], bool)` |
| TypeScript | `Node.compose(value, children)` | `node.decompose()` | `node.own` → `T` | `node.at(path)` → `Node<T> \| undefined` |
| Python | `Node.compose(value, children)` | `node.decompose()` | `node.own` → `T` | `node.at(path)` → `Node[T] \| None` |

Construction refuses duplicate byte keys. Path lookup traverses children only;
the empty path selects the node itself. Check lookup success before reading the
own value: an existing node holding `undefined`, `None`, `null` or another empty
payload must remain distinguishable from a missing node. In TypeScript, for
example, `node.at(path)?.own` collapses those cases when `T` includes `undefined`.

```ts
import { Node } from "@bitspark/deixis-core";

const key = new TextEncoder().encode("child");
const root = Node.compose("parent", [[key, Node.compose("child", [])]]);
const found = root.at([key]);
if (found !== undefined) console.log(found.own); // "child"

const { own, children } = root.decompose();
const rebuilt = Node.compose(own, children);
console.assert(root.equalBy(rebuilt, (a, b) => a === b));
```

To retain the original leaf/structure distinction, choose `Node[Option[U]]`:

```text
Leaf(u)   ↦ Node(Some(u), {})
Struct(m) ↦ Node(None, { k ↦ embed(m[k]) })
```

This embedding preserves native paths and, with lifted option equality, identity.
It does not prevent later attachment to a formerly terminal node. Rust uses
`Option<U>`; Go supplies the opt-in `deixis.Option[U]`; TypeScript supplies
`Option<U>` and `some`; Python supplies `Some[U] | None`.

The optional-core model from the intervening, unreleased ADR 0009 implementation
is likewise the explicit specialization `Node[Option[U]]`. Its callers must now
supply a relation on the entire option. The generic core does not unwrap `Some`
or decide that `None` is unequal to a present payload. Choose the usual lifted
option equality when those are the desired semantics.

Derived mapping applies its function to every own value. For optional payloads,
use an option-preserving function explicitly if absence should survive mapping.
Complete parts also support contexts, cuts, replacement and exact fresh
attachment. These are structural laws and derived operations, not additional
public mutation or undo APIs.

The positional key profile keeps its spelling and `deixis-pos-v1` identifier.
The slot-member set profile now explicitly uses `Node[Option[U]]`, with `None` at
the container and childless `Some(u)` members. Its recognizer rejects nodes
outside that image.

## Distribution and scope

Validation of the release source includes **368 black-box requests in each of
four languages**, including all **121 independently authored mandatory-model
cases**. The language format, lint, type and unit checks pass, as do specification,
link, vector-pin and measured-claim checks. Both publishable TypeScript packages
were packed and installed into a separate directory, where their exports,
reconstruction and null-like payload behavior were exercised. Paper v4 compiles
in two passes with no undefined references or overfull boxes; every page was
rendered and visually reviewed.

The repository-wide source tag is `v0.2.0`. The coordinated Rust and TypeScript
package versions are `0.2.0`, including the unchanged positional implementation.
The tag workflow publishes `@bitspark/deixis-core` and `@bitspark/deixis-pos` to
GitHub Packages. Go and Rust consume the source tag; Python remains source-only,
and the TypeScript set package remains private because it imports the sibling
core build.

This is a core and profile release. It does not freeze or publish a canonical
codec: [CODEC.md](../CODEC.md) remains a candidate for an earlier tree model, and
the separate grammar, proof, independent-review and freeze work remains open in
[issue #1](https://github.com/Bitspark/deixis/issues/1). No old byte or address
compatibility is promised for a future mandatory-value encoding.

Wire, nightseam, bittree and ontos adoption is recorded separately from deixis
delivery. This release does not certify or change those consumers. See
[bitwire #29](https://github.com/Bitspark/bitwire/issues/29) for the Wire
interpretation and [EVIDENCE.md](../EVIDENCE.md) for measured coverage and proof
status.
